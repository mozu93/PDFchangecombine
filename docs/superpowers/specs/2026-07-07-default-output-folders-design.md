# 出力先の既定フォルダ化・永続化廃止 設計書

日付: 2026-07-07
対象バージョン: v1.21.2 以降

## 背景・目的

現在、4機能(PDF変換・資料NO挿入・PDF結合・ページ番号挿入)の出力先は
`settings.json` に永続化され、次回起動時に前回の出力先が復元される。
このため「前回とは別の案件のフォルダに保存される」事故が起きやすい。

本変更では出力先の記憶を廃止し、常に「変換元ファイルのあるフォルダ配下の
機能別フォルダ」を既定の出力先とする。

## 仕様

### 1. 出力先の永続化廃止

- `src/utils/settings.py` の `DEFAULT_SETTINGS` から以下の4キーを削除する:
  - `conversion_output_dir`
  - `document_output_dir`
  - `combination_output_dir`
  - `pagenumber_output_dir`
- 保存・復元処理(`_collect_current_settings` / 起動時の復元)からも対応する
  4項目を削除する。
- 既存の `settings.json` に残っている値は、`load_settings()` が
  `DEFAULT_SETTINGS` に存在するキーのみマージする仕組みのため自然に無視される。

### 2. 既定の出力先(実行時に解決)

手動指定がない場合、実行時に以下のフォルダを作成(存在すればそのまま使用)して
保存する。基準は**リスト先頭のファイルの親フォルダ**。

| 機能 | 既定フォルダ名 |
|---|---|
| PDF変換 | `PDF変換済` |
| 資料NO挿入 | `資料NO挿入済` |
| PDF結合 | `PDF結合済` |
| ページ番号挿入 | `ページ番号挿入済` |

- GUI側に共通ヘルパー(例: `_resolve_output_dir(override, files, subfolder)`)を
  設け、実行時に解決した具体パスをコア処理へ渡す。
- コア処理(converter / combiner / document_number / page_number)の
  インターフェースは変更しない。
- ファイル追加時に出力先へ親フォルダを自動セットしている既存処理は削除する。

### 3. 手動指定(📂 変更)の扱い

- 手動指定した場合はそのフォルダ**直下**に保存する(サブフォルダは作らない)。
- 指定は**アプリ終了まで**有効。再起動すると既定に戻る。
- `self.*_output_dir` は「手動指定があった場合のみ値を持つ」変数として扱う
  (空 = 既定動作)。

### 4. 出力先ラベル・確認ダイアログの表示

| 状態 | 表示 |
|---|---|
| 未指定・ファイル未追加 | 「変換元フォルダ内に「PDF変換済」を作成(既定)」等の説明文 |
| 未指定・ファイル追加済み | 解決済みの既定パス(例: `C:\...\案件A\PDF変換済`) |
| 手動指定済み | 指定パス(現行どおり) |

- 実行前の確認ダイアログの「出力先」表示も同じ解決結果を表示する。
- ファイルリストのクリア時は、手動指定がなければ表示を説明文に戻す。

### 5. PDF結合のファイル名

- 現行: `結合_{YYYYMMDD_HHMMSS}.pdf`
- 変更後: `【結合】{リスト先頭のファイル名(拡張子除く)}.pdf`
- 同名ファイルが存在する場合は既存の `OutputManager.get_unique_output_path`
  により連番を付与する(非破壊出力は維持)。

### 6. 変更しないこと

- コア変換・結合処理のロジックおよびインターフェース
- 非破壊出力、元ファイルの「変換元」フォルダへの退避、PDF修復、
  クラウドパス対策などの既存動作
- 出力先以外の設定項目の永続化(フォント、スイッチ類など)

## エラーハンドリング

- 既定フォルダの作成に失敗した場合(権限なし等)は、エラーメッセージを表示して
  処理を中断する(親フォルダ直下への保存には黙ってフォールバックしない)。

## テスト

- `tests/` の既存テストを実行し、出力先関連のテストがあれば新仕様に合わせて更新。
- 手動確認: 4機能それぞれで (a) 既定フォルダ生成と保存、(b) 手動指定時の直下保存、
  (c) 再起動後に既定へ戻ること、(d) 結合ファイル名 `【結合】〜.pdf` を確認する。
